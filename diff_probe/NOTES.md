# diff_probe 실험 정리 (2026-10-31)

선지끼리의 차이(바뀐 단어)에 집중해 리더보드 0.43 정체를 넘으려 한 실험의 기록이다. 결론부터 적는다.

- 학습 없는 **선지 거리 방식(hyuwooma)이 0.52**로 여전히 최고다.
- 바뀐 단어만 보는 모델 **marked_v1, marked_v2**는 리더보드 **0.413, 0.432**다. 기존 학습 모델(minimal 0.426, baseline_v2 0.439)과 같은 0.41~0.44 구간이다.
- 이 문서에서 **baseline_v2**는 `baseline_v2/` 폴더의 기존 모델(LB 0.439)이고, **marked_v1·marked_v2**는 이 폴더(`diff_probe/`)의 바뀐 단어 표시 모델이다. 서로 다른 모델이다.
- 원인은 학습 오답이 전부 규칙 오답이었다는 데 있다. 모델은 영상이 아니라 규칙 오답의 흔적을 배웠다. 자연스러운 Qwen 오답 앞에서는 무작위 수준이다.

## 1. 리더보드

무작위는 0.375다. 점수는 1위 1, 2위 0.5, 3위 0.25, 4위 0.125, 5위 0이다.

| 제출 | 내용 | LB |
|---|---|---|
| starter | 운영진 baseline | 0.3499 |
| minimal | starter + 규칙 오답, listwise CE | 0.4260 |
| baseline_v2 (`baseline_v2/`, v2_submission_int8) | DINOv2 + SigLIP + MPNet, 프레임 순서 transformer | 0.4391 |
| **hyuwooma** | 학습·영상 없음. 다른 선지 4개와의 평균 글자 거리가 가장 작은 선지가 1위 | **0.52** |
| marked_v1 ep14 (`diff_probe/`) | 바뀐 단어 표시 모델, 기준 선지 방식(ref) | 0.4132 |
| marked_v2 ep12 (`diff_probe/`) | 바뀐 단어 표시 모델, 모든 선지 같은 자리 방식(slots) | 0.4319 |

학습한 모델 다섯 개는 로컬 점수가 0.72~0.87로 제각각인데도 리더보드는 모두 0.41~0.44다. 공개 30% 분할의 잡음(약 ±0.02)을 생각하면 서로 구분되지 않는다.

## 2. 출발점: 왜 한 단어 차이가 안 보이나

MPNet 문장 평균 벡터로 정답과 동사 하나만 바꾼 오답을 비교했다(Train 400쌍).

| 비교 | cosine |
|---|---|
| 문장 평균 벡터 | 0.993~0.997 (문장이 길수록 1에 가까움) |
| 바뀐 단어 토큰만 | 0.78~0.81 |

50단어 문장에서 한 단어 차이는 평균에 묻힌다. 그래서 "선지끼리 다른 단어에서만 점수를 내자"는 방향을 잡았다.

## 3. 선지 거리 방식이 맞히는 이유: 자리별 다수결

hyuwooma는 다른 선지와 가장 덜 다른 선지를 고른다. 오답이 모두 정답을 고쳐 만든 것이라면, 선지 5개를 단어 자리별로 놓았을 때 원래 단어는 그 자리를 안 고친 선지 전부가 갖는다. 따라서 이 방식은 사실상 **자리별 다수결**이다.

- 어떤 수정도 오답 3개 이상에 들어가지 않으면 원래 단어가 매 자리 3표 이상으로 이긴다. 정답이 1위다.
- 한 수정이 오답 3개에 들어가면({a, b, a+b, a+c}) 그 자리는 고친 단어가 이긴다. 중심이 오답으로 넘어간다.

규칙 오답으로 구조만 바꾼 검증 세트 H1~H7(`sim_valsets.py`, 검증 에피소드 626개, 첫 문장)에서의 결과다. 다수결로 보면 세 묶음뿐이다.

| 묶음 | 세트 | 한 수정이 들어간 오답 수 | 글자 거리 | 단어 자리 거리 |
|---|---|---|---|---|
| ① | H1 서로 다른 곳, H2 같은 단어, H3 오답마다 두 곳 | 1 | 0.93~0.99 | 0.93~0.99 |
| ② | H4 {a, b, a+c, b+d}, H6 {a, b, a+b, c} | 2 | 0.66~0.78 | 0.81~0.92 |
| ③ | H7 {a, b, a+b, a+c} | 3 | 0.27 | 0.39 |

H5는 H1~H4를 섞은 세트다. 글자 거리 0.75, 단어 자리 거리 0.86이다.

## 4. SmolVLM-256M zero-shot (`vlm_probe.py`)

바뀐 자리만 보여 주고 고르게 했다. 영상을 쓰지 않았다.
- 프레임 없이 0.53~0.63, 정상 0.48~0.55, 역순 ≈ 정상.
- 선지 2개에서도 마지막 보기를 94~99% 고르는 위치 편향이 있다(Zheng et al. ICLR'24 등에서 보고된 현상).
- 학습 없이 쓰기는 어렵다고 보고 접었다.

## 5. 바뀐 단어 표시 모델 (marked verifier)

- **영상**: DINOv2 + SigLIP 프레임 특징(동결, 캐시)을 2층 transformer에 넣는다. 프레임 순서 임베딩을 쓴다.
- **문장**: MPNet 토큰(동결)에 표시 임베딩(바뀐 단어 1, 공통 0)을 더한다. 2층 decoder로 프레임을 cross-attention한다.
- **점수**: 표시된 토큰의 점수 평균이 선지 점수다. 455만 파라미터를 학습한다.
- **손실**: 정답 + 규칙 오답 4개 listwise CE, 그리고 영상 손실(같은 정답 문장을 자기 영상 / 역재생 / 다른 영상 3개와 겨룸).
- **학습**: 15 epoch. epoch는 검증 에피소드를 반 A / 반 B로 나눠 A로 고르고 B로 보고한다(`eval_ckpts.py`).

표시 방식이 두 가지다.
- **marked_v1 (ref)**: 중심 선지를 기준으로 기준과 다른 곳만 표시한다. 기준 선지에는 모든 수정 자리가 표시된다. 학습 데이터에서는 기준이 거의 늘 정답이라, "표시가 고르게 퍼진 선지 = 정답"이라는 지름길이 생긴다. 사실상 거리 방식을 몰래 배운다.
- **marked_v2 (slots)**: 선지끼리 갈리는 자리를 다섯 선지 모두에 똑같이 표시한다. 지름길을 막았다.

규칙 오답 세트, 반 B 결과:

| 세트 | 단어 자리 거리 | marked_v1 ep14 | marked_v2 ep14 |
|---|---|---|---|
| H1 | 0.989 | 0.953 | 0.789 |
| H2 | 0.927 | 0.907 | 0.765 |
| H3 | 0.948 | 0.920 | 0.915 |
| H4 | 0.809 | 0.869 | 0.852 |
| H5 | 0.860 | 0.864 | 0.838 |
| H6 | 0.920 | 0.894 | 0.838 |
| H7 | 0.388 | 0.653 | 0.890 |

이 표만 보면 marked_v2가 H7을 풀고 marked_v1은 거리 방식을 넘는다. 하지만 리더보드는 둘 다 0.41~0.43이었다. 규칙 오답 세트는 리더보드를 예측하지 못한다.

## 6. 자연스러운 오답으로 다시 재기 (Qwen 세트)

팀 Qwen 증강 데이터(HF `SANGchu-03/INThon_Augmented`, Qwen3-4B-Instruct-2507 fp16, greedy)로 검증 세트를 짰다(`qwen_valsets.py`). 검증 에피소드만 썼고, 반 B로 쟀다. 값은 전체 설명 / 첫 문장 순서다.

| 세트 | 글자 거리 | 단어 자리 거리 | marked_v1 ep14 | marked_v2 ep12 |
|---|---|---|---|---|
| 정답 + 한 군데 고친 오답 4개 | 0.98 / 0.97 | 0.93 / 0.97 | 0.74 / 0.85 | 0.39 / 0.51 |
| {a, b, a+b, c} | 0.95 / 0.93 | 0.91 / 0.90 | 0.62 / 0.78 | 0.40 / 0.56 |
| {a, b, a+b, a+c} | 0.35 / 0.31 | 0.36 / 0.33 | 0.31 / 0.43 | 0.39 / 0.56 |
| 정답 원문 + 다르게 쓴 문장을 고친 오답 4개 | 0.50 / 0.59 | 0.17 / 0.33 | 0.57 / 0.53 | 0.66 / 0.69 |

- **marked_v2는 자연스러운 오답 앞에서 무작위 수준이다.** 다른 영상을 넣어도 0.03~0.06만 떨어진다. 규칙 세트에서 얻은 점수는 영상이 아니라 규칙 오답의 흔적에서 나온 것이다.
- **marked_v1의 높은 칸은 거리 방식에서 빌려 온 점수다.** 거리 방식이 무너지는 {a, b, a+b, a+c}에서는 같이 무너진다.
- **마지막 줄에서 marked_v2가 0.66~0.69인 것도 영상 덕이 아니다.** 정답만 Train 원문 문체라서, 문체로 정답을 알아본 것이다. (inthon-93 측정으로는 baseline_v2도 이 세트에서 0.72다. 같은 이유다.)
- epoch별로 봐도 경향은 같다. 초반 epoch가 낫지 않다.

## 7. 리더보드 순서를 재현하는 검증 세트 (inthon-93 세션, `validator/README.md`)

starter, minimal, baseline_v2, marked_v1을 서버 채점 방식대로 여러 세트에서 쟀다. **리더보드 순서(starter < 학습 모델들 < 거리 방식)를 재현하는 세트나 혼합은 없었다.**
- 오답이 한 곳만 고친 세트: 거리 방식이 0.97 이상이다.
- 수정을 여러 오답이 공유하는 세트: 거리 방식이 0.2~0.35다.
- 섞으면 순서가 맞는 비율이 한 점뿐이다. 그마저 starter가 0.47~0.50으로 리더보드(0.35)와 멀다.
- starter를 리더보드 값에 맞춘 세트는 af_full뿐이다(0.352). 그 세트에서는 거리 방식이 1.0에 가깝다.

오답 구조만으로는 리더보드가 설명되지 않는다. test가 다른 벤치마크라 영상과 문체 자체가 다르다는 점이 더 큰 원인으로 보인다.

## 8. 남은 것

- 규칙 오답 학습은 더 하지 않는다. 다음 학습은 Qwen 오답(A′, B′)과 다르게 쓴 정답(B)으로 한다. 학습 에피소드 3,544개만 쓴다.
- 학습 전에 SigLIP zero-shot을 Qwen 세트에서 잰다. 영상으로 얼마나 가려낼 수 있는지의 기준선이다.
- 단어 자리 거리 제출(`submissions/span_centrality.zip`)은 아직 내지 않았다.
  - 오답이 단어만 고친 구조라면 0.52를 넘는다.
  - 다시 쓴 구조라면 0.2~0.3으로 떨어진다(para_negs 0.17~0.33).
  - 점수 개선용이 아니라 test 구조를 가르는 실험이다.
  - **결과 (2026-11-01): 리더보드 0.5661.** byte(0.52)보다 높다. span이 byte를 이기는 것은 여러 오답이 **긴 수정**(동작 덧붙이기, 구절 옮기기)을 공유할 때뿐이라, test는 단어 수정 오답이 수정을 공유하는 구조로 본다. 다시 쓴 문장 구조(para_negs)는 주된 구조가 아니다.

## 9. 영상 판단기 (2026-11-01)

거리 방식이 지는 곳은 수정을 여러 오답이 공유해 정답이 2~3위로 밀리는 에피소드다. 그 후보들은 수정 한 곳만 다르므로, 영상으로 그 순서만 정하면 된다. 평가는 `validator/`의 보정 검증기와 `validator/judges/`를 쓴다.

- **SigLIP zero-shot**(`siglip_pairs.py`): 절을 프레임에 순서대로 맞춘다. 정답 vs 한 곳 수정 쌍에서 물체·속성 0.75~0.79, 동작 방향·순서 0.52~0.58.
- **글 편향 제거**: 같은 문장을 Train 참조 영상 64개에 넣은 평균 점수를 뺀다. 다른 에피소드 영상을 넣으면 정확도가 0.5가 되어야 한다.
- **학습 헤드**(`pair_head.py`): 동결 DINOv2+SigLIP 프레임 + SigLIP 절, Qwen 한 곳 수정 오답으로 학습. 다른 영상에서 정답과 오답 점수를 같게 하는 벌점으로 문장 지름길을 막는다.
- **역재생 손실, 클립 이어 붙이기 손실**(Paxion, Test of Time 방식): 효과 없음. 프레임이 9~20장으로 띄엄띄엄이고, 물체가 나왔다 사라지는 클립이 많다.
- **공간 헤드**(`patch_head.py`, `cache_patches.py`): DINOv2 패치 4×4 격자 + 직전 프레임과의 차이. 모든 수정 종류에서 기존 헤드보다 낫다(동작 0.60/0.66 → 0.64/0.75). 참조 영상 64개는 학습에서 뺀다(`--exclude`).

span + 0.3 z(SigLIP) + 0.3 z(공간 헤드), 보정 검증기 반 B: full 0.710, short 0.821 (span 단독 0.576 / 0.560). 다른 영상을 넣으면 span 단독보다 낮아진다.

- **생성기가 바뀌면 이득이 준다.** Claude가 쓴 {a, b, a+b, a+c}에서 0.635, 같은 구조의 Qwen 셀에서 0.767. 순위(공간 헤드 > 기존 헤드 > SigLIP만)는 그대로다.
- **편향 제거 ablation** (`validator/judges/robust_eval.py`): SigLIP은 네 세트 모두에서 빼는 쪽이 낫다(+0.00~0.03). 공간 헤드는 잡음 범위(±0.015)지만 빼면 다른 영상 점수가 낮아진다(문장 의존이 줄어든다). 제출본은 둘 다 뺀다. **리더보드로는 아직 확인하지 않았다.**
- 제출본: `submissions/video_judge_patch.zip` (543MB, `export_judge.py --head-type patch`). 서버 방식 점검(sentencepiece 없음, 오프라인)에서 실험 점수와 일치, 에피소드당 0.17초(A100).

**리더보드: `video_judge_patch` 0.4952** (2026-11-01). span 단독 0.5661보다 0.07 낮다. 로컬 +0.13이 test에서는 −0.07이 됐다.
- 같은 공식에 무작위 판단기를 넣은 시뮬레이션: 쌍 정확도가 0.50이면 0.47, 0.58이면 0.57이다. 0.4952는 test 쌍 정확도 약 0.52에 해당한다. test 영상에서는 판단기가 거의 찍기 수준이었다.
- 로컬에서도 약한 동작·순서 수정이 test에 많다면 설명된다(TemporalBench 통계: 동작 종류·순서·방향 위주). 영상 도메인 차이(PerceptionTest → 다른 벤치마크)로도 설명된다. 둘을 가르려면 다른 도메인 영상이 필요하다.
- 학습 모델 5개(0.41~0.44)에 이어, 영상 판단기도 로컬 검증기가 크게 과대평가했다. 보정 검증기는 영상을 안 보는 방법에만 맞는다.

|---|---|
